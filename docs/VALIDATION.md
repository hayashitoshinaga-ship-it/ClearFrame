# ClearFrame 验证记录

验证日期：2026-11-08。环境：Windows x64、Python 3.10.10、NVIDIA GeForce RTX 5090、约 95.3 GiB 系统内存。

## 0.2.0 保存与队列功能验证

自动检查共 52 项：原有算法、服务、硬件测试，加上保存位置与导出的 HTTP 集成、14 项存储测试。JavaScript 语法和 diff 检查通过。最终全套运行有一次旧来源拒绝用例在客户端读取响应时遇到 Windows 10053 连接中止；随后重跑全部 16 项 HTTP 用例通过，其余 36 项在该全套运行中通过。未将瞬断视为已定位并修复的程序缺陷。

覆盖：保存目录持久化及配置替换失败回滚，显式测试目录优先，恢复默认后跟随搬迁的新根目录，不可用的持久目录暂回默认且不丢原偏好；提交时锁定输出目录；同名 PNG/JSON 冲突与并发发布不覆盖；导出中断不登记成功或留下最终半成品；重新处理时仍可导出上次成功结果，未完成图片跳过，导出文件夹同秒重名追加编号。

Edge 界面实测使用隔离的 7867 服务与 `work/output-feature-validation/`，不修改正式保存偏好：

- 更改保存位置时相对路径显示中文错误；带中文和空格的绝对目录保存成功，页面路径和偏好文件一致。恢复默认按钮也已实测。
- 浏览器拖放面板拖入真实 Aris、Kei PNG 后，队列为 2，预览自动选中最后导入的 Kei；没有自动开始任务。此项验证浏览器文件拖放通道，不等同于资源管理器跨窗口拖拽复测。
- 手动批量运行真实 GPU 处理，生成 `Aris_二次元人物_默认_强度40.png`、`Kei_二次元人物_默认_强度40.png`，页面下载属性使用同名文件。
- 将 Kei 改为轻柔、强度 35 并再次处理，生成 `Kei_二次元人物_轻柔_强度35.png`；旧文件仍保留。
- 改保存目录后导出旧结果，成功收集 Aris 默认40与 Kei 轻柔35两个最新结果，跳过新增但未处理的第三张图片。导出弹窗显示 2 张成功、1 张跳过；四个 PNG/JSON 文件与源文件哈希逐一相同，没有导出 Kei 较旧版本。
- 自动保存卡及导出弹窗的“打开文件夹”均实际启动了资源管理器；导出窗口地址栏为指定导出目录，列表中包含正确的四个文件。
- 退出后新增加的打开、更改目录及导出按钮全部停用，测试服务正常退出。

保存位置卡已移至当前任务下方，使打开和更改入口更容易找到。以下为 0.1.0 的基础算法与此前复测记录，仍保留其测试边界。

## RTX 5090 实测

输入为本地提供的 1024×1024 爱丽丝插画，设置为「二次元人物／场景默认／强度 40」。预缩比例 72%，L0 λ 约 0.000480，结果与原图混合比例约 55.1%。

| 路径 | 耗时 | 实际主要计算设备 |
|---|---:|---|
| 处理函数首次调用，模型已下载 | 3.060 秒 | CUDA：动漫重建、L0 |
| 同进程再次调用，模型已加载 | 0.741 秒 | CUDA：动漫重建、L0 |
| 隐藏服务中的首次 HTTP 任务 | 3.95 秒 | CUDA：动漫重建、L0 |

前两项计时从处理函数进入到 PNG 保存结束，不含 Python 启动和依赖/模型下载。它们不是跨电脑或不同图片尺寸的性能保证。PyTorch 记录的峰值已分配显存约 4.291 GiB，区别于界面显示的整张显卡总体显存占用。

结果尺寸正确、进度单调、真实阶段设备为 CUDA。第二次调用禁止了模型网络下载入口，缓存处理仍成功。HTTP 下载返回有效 PNG 和附件响应头，硬件接口确认 `cuda_available=true`。处理结果已作目视检查，未见明显损坏；未对四个场景开展大规模画质基准测试。

仍有两项验证边界：Windows 资源管理器截图连续超时，因此未验证资源管理器到浏览器的跨窗口系统拖拽；上述测试只证明真实 File 数据在浏览器拖放通道中可以导入。点击“保存结果”的请求到达了服务，但浏览器下载完成事件两次超时，系统下载目录未发现相应副本；浏览器策略也禁止自动化打开内部下载管理页。因此不能宣称浏览器另存副本已完成。自动保存文件、附件响应及逐字节一致性已独立验证。

旧版 PyTorch 1.13.1+cu117 在 RTX 5090 上会触发长时间初始化。应用现于运算前识别该组合：自动模式退回 CPU，显式 GPU 模式提示更新环境；硬件检测另有进程隔离与超时清理。此兼容策略已在该旧环境实测，不影响当前独立 cu128 环境。
