验证日期：2026-11-08。环境：Windows x64、Python 3.10.10、NVIDIA GeForce RTX 5090、约 95.3 GiB 系统内存。

独立 `.venv` 使用 PyTorch 2.7.1+cu128、torchvision 0.22.1+cu128、NumPy 2.2.6、Pillow 12.3.0、spandrel 0.4.2、OpenCV 4.14.0.94、psutil 7.2.2。`pip check` 通过。动漫模型从原作者发布地址取得，并核对上游固定的 SHA-256。

31 项 Python 测试全部通过。覆盖预设与输入校验、零强度像素恒等、透明通道和 ICC、浮点/16 位导入、真实 CPU L0 与 NLM、NLM 分块一致性、模型缓存损坏、处理取消、HTTP 手动任务生命周期、来源校验、唯一输出和 JSON 记录、后台退出以及检测子进程回收。

JavaScript 语法检查通过。启动器真实启动了隐藏本地服务，健康检查正常；此启动检查替换了打开浏览器的最后一步，以免重复打开窗口。服务已通过 HTTP 完整执行一次真实 GPU 导入、排队、处理和下载。

## RTX 5090 实测

输入为本地提供的 1024×1024 爱丽丝插画，设置为「二次元人物／场景默认／强度 40」。预缩比例 72%，L0 λ 约 0.000480，结果与原图混合比例约 55.1%。

| 路径 | 耗时 | 实际主要计算设备 |
|---|---:|---|
| 处理函数首次调用，模型已下载 | 3.060 秒 | CUDA：动漫重建、L0 |
| 同进程再次调用，模型已加载 | 0.741 秒 | CUDA：动漫重建、L0 |
| 隐藏服务中的首次 HTTP 任务 | 3.95 秒 | CUDA：动漫重建、L0 |

前两项计时从处理函数进入到 PNG 保存结束，不含 Python 启动和依赖/模型下载。它们不是跨电脑或不同图片尺寸的性能保证。PyTorch 记录的峰值已分配显存约 4.291 GiB，区别于界面显示的整张显卡总体显存占用。

结果尺寸正确、进度单调、真实阶段设备为 CUDA。第二次调用禁止了模型网络下载入口，缓存处理仍成功。HTTP 下载返回有效 PNG 和附件响应头，硬件接口确认 `cuda_available=true`。处理结果已作目视检查，未见明显损坏；未对四个场景开展大规模画质基准测试。

## 界面检查与边界

浏览器检查通过：多文件选择导入后保持待处理、自定义 CPU 组合、手动开始、批量队列、零强度输出、原图/结果/滑动对比、100% 放大、强度调整不自动重跑、旧结果提示以及运行中取消。文件拖放事件做了代码检查，未单独自动化模拟系统文件拖放。

浏览器下载事件监听未返回完成事件；下载链接和 HTTP 附件内容已单独验证。浏览器自动化在退出确认阶段因无法可靠识别窗口 URL 而停止。随后退出确认改成页面内对话框，并通过语法与代码检查；这一最终对话框未再次进行浏览器实测。退出 HTTP 接口、任务取消和子进程清理均有自动化检查。

旧版 PyTorch 1.13.1+cu117 在 RTX 5090 上会触发长时间初始化。应用现于运算前识别该组合：自动模式退回 CPU，显式 GPU 模式提示更新环境；硬件检测另有进程隔离与超时清理。此兼容策略已在该旧环境实测，不影响当前独立 cu128 环境。
